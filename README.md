# Скиллы Codex на русском: сводка изменений и проверка учебного проекта

Два собственных навыка Codex со скриптами: сводка изменений Git и статическая проверка учебного Python-проекта.
Для тех, кто хочет понять формат `SKILL.md` на примерах с заранее известным результатом.

## Быстрый старт за 1 минуту

Нужны Python 3.9+ и Git. В папке скачанного проекта выполните:

```bash
python3 -B tools/validate_skills.py
python3 -B examples/demo.py
python3 -B -m unittest discover -s tests -v
```

Проверяющий найдет два навыка. Демо покажет JSON со сводкой Git и пятью успешными проверками учебного проекта. Затем пройдут 19 тестов. Аккаунт, подписка, Codex и сеть для этих команд не нужны. Демо создает временный Git-репозиторий внутри `.test-tmp/` и убирает его после работы.

## Какой навык выбрать

| Навык | Когда нужен | Результат |
| --- | --- | --- |
| [repo-change-summary](.agents/skills/repo-change-summary/SKILL.md) | Посмотреть локальные правки перед передачей работы | Отдельные списки staged, unstaged, untracked; состояние проверок |
| [check-learning-project](.agents/skills/check-learning-project/SKILL.md) | Проверить маленький учебный Python-проект | Структура, описание, точка входа, наличие тестов, синтаксис |

Оба скрипта только читают выбранный проект и печатают результат. Первый не читает содержимое файлов; второй разбирает Python через AST, без запуска кода и тестов.

## Установка для Codex

Навыки уже находятся в проектной папке `.agents/skills/`. Запустите Codex из корня этого репозитория и выберите навык через `/skills` или упомяните его с `$`.

В другом проекте нужна копия всей папки навыка в `<проект>/.agents/skills/`. Личные навыки размещаются в `~/.agents/skills/`. Не перезаписывайте одноименный навык без проверки. По текущей документации Codex замечает изменения автоматически; если навык не появился, перезапустите Codex.

Правила проекта `AGENTS.md` и навык решают разные задачи: первые задают инструкции проекта, второй описывает отдельную работу. Для этих примеров дополнительный `AGENTS.md` не нужен. При работе действуют инструкции вашего проекта и настройки разрешений Codex.

## Два запуска

Явный вызов в Codex:

```text
$repo-change-summary Покажи сводку локальных изменений в текущем репозитории. Файлы не меняй.
```

Тот же скрипт без Codex, из корня этого репозитория:

```bash
python3 -B .agents/skills/repo-change-summary/scripts/summarize.py --repo .
```

Нужен Git-репозиторий хотя бы с одним коммитом. Подготовленные изменения сравниваются с HEAD, неподготовленные - с индексом. Переименования представлены удалением и добавлением. Игнорируемые Git файлы не включаются. Скрипт не обновляет индекс и не запускает проверки. При ошибке Git он возвращает код 2, вместо пустой успешной сводки.

Второй явный вызов:

```text
$check-learning-project Проверь fixtures/project-good. Покажи пройденные пункты и ограничения проверки. Файлы не меняй.
```

Без Codex:

```bash
python3 -B .agents/skills/check-learning-project/scripts/check_project.py --project fixtures/project-good
```

Замените `project-good` на `project-broken`, чтобы получить отказ с кодом 1. Код 2 означает, что передана неподходящая папка. В проекте нужны `project.json` с полями `title` и `entry`, непустой `README.md`, точка входа `.py` и файл `tests/test_*.py`.

## Что считать правильным ответом

В бесплатном демо сводка должна показать `main.py` в staged, `README.md` в unstaged и `notes.txt` в untracked. Поле `checks` должно содержать `не запускались`. Один файл в настоящем проекте может одновременно иметь подготовленные и неподготовленные изменения.

Для исправного проекта все пять полей `checks` равны `true`, `ok` тоже `true`. В сломанном примере есть ошибка синтаксиса, пустое название, нет README и тестов. Проверка сообщает об этом без запуска программы.

| Файл | Для сравнения |
| --- | --- |
| [Результат демо](fixtures/expected-demo.json) | Полный ожидаемый результат бесплатного демо |
| [Исправный проект](fixtures/expected-project-good.json) | Все пункты проверки пройдены |
| [Ошибки проекта](fixtures/expected-project-broken.json) | Результат проверки сломанного примера |

Это эталоны вывода скриптов. Формулировки ответа Codex могут отличаться; списки файлов, статусы и оговорка о незапущенных тестах должны сохраниться. Ответы Codex в реальной сессии не проверялись. При явном вызове Codex используются ваши обычные условия доступа и лимиты.

## Структура SKILL.md

```text
.agents/skills/
  repo-change-summary/
    SKILL.md
    scripts/summarize.py
  check-learning-project/
    SKILL.md
    scripts/check_project.py
tools/validate_skills.py
fixtures/
  project-good/
  project-broken/
  expected-demo.json
examples/demo.py
tests/test_examples.py
```

В начале `SKILL.md` стоит YAML-блок между строками `---` с полями `name` и `description`. После него идут инструкции. Описание объясняет, когда выбирать навык. Путь к собственному скрипту в инструкции считается от папки навыка.

`tools/validate_skills.py` проверяет наличие файла, строковые поля, совпадение `name` с папкой, непустые инструкции и ошибки простого frontmatter. Можно передать путь к отдельной папке навыка. Это проверяющий формата примеров, не полная реализация YAML или проверка качества ответа модели. Сложный вложенный YAML явно отмечается как неподдержанный.

## Версия, источники и ограничения

Формат проверен 24.10.2026 по [документации навыков OpenAI](https://developers.openai.com/codex/skills/) и [документации AGENTS.md](https://developers.openai.com/codex/guides/agents-md/). Эти адреса сейчас перенаправляют на официальный сайт ChatGPT Learn. Установленный CLI - **codex-cli 0.163.0**; запуск моделей в проверку не входил.

Статическая проверка рассчитана на небольшие учебные проекты: до 200 Python-файлов, до 1 МиБ на читаемый файл. Скрытые каталоги пропускаются, символические ссылки не обходятся. Зависимости и логика программы не проверяются. Успешный разбор синтаксиса не доказывает успешное выполнение тестов. Вывод Git содержит названия файлов выбранного проекта - проверяйте его перед внешней отправкой.
